[컴포넌트 정의]

* 함수형 컴포넌트 정의

예)
export default function App(){
	return(
		<>
			<h1>Hello, Function Component</h1>
		</>
	);
}


이를 함수 선언문 방식이라고 하며, 컴포넌트는 function 키워드로 정의하고 jsx를 return 문 안에 작성한다.
그리고 이 컴포넌트를 다른 파일에서 사용할 수 있도록 내보내기 (export) 한다.


컴포넌트를 내보낼 때는 두 가지 방식 중 하나를 선택할수있다.

export 키워드만 사용하면 컴포넌트를 불러오는 쪽에서 중괄호 {} 를 사용해 불러와야 한다.

반면에 export default 키워드를 사용하면 중괄호 없이!! 바로 불러올 수 있다.

또한!! export 를 사용하면 하나의 파일에서 여러 컴포넌트를 내보 낼 수 있지만, 

	export default는 한 파일에서 하나의 기본 컴포넌트만 내보낼 수 있다.

예)
import { App } from './App.tsx'; // export function App() { ... } 사용 시
import App from './App.tsx'; // export default function App() { ... } 사용 시

컴포넌트를 정의하고 내보내는 방식은 프로젝트 구조나 협업 스타일에 따라 달라질수 있다.
하지만 초보자라면 먼저 export default 방식을 익히고, 필요할 때 export 방식도 함께 사용하는 것이 좋다.

* 다른 정의 방식

> 함수형 컴포넌트는 function 키워드를 사용한 함수 선언문 방식 외에도 함수 표현식이나 "화살표 함수(arrow function)를 사용하여 정의할수도 있다.

함수표현식)
const App = function App() {
	return(
		<>
			<h1>Hello, Function Component</h1>
		</>
	);
}
export default App;

화살표함수)
const App = () => {
	return(
		<>
			<h1>Hello, Function Component</h1>
		</>
	);
}
export default App;


=> 위의 방식 중 어떤방식으로도 정상적으로 동작한다. 하지만 "함수선언문"방식을 가장 많이 사용한다.
코드의 가독성이 좋고, 함수 이름이 명확하게 보이기 떄문이다.

> 리액트 애플리케이션은 App zㅓㅁ포넌트에 여러 하위 컴포넌트를 포함하면서 전체 ui를 구성한다.
즉, 하나의 컴포넌트 안에 또 다른 컴포넌트를 포함하는 방식으로 계층적 구조가 형성된다.
이렇게 컴포넌트들이 연결된 구조를 "컴포넌트 트리" 라고 한다.

App 컴포넌트는 리액트 애플리케이션에서 가장 바깥쪽에 위치하는 컴포넌트이다.
그래서 App을 "루트 컴포넌트"라고 한다.
모든 컴포넌트는 이 루트 컴포넌트를 통해 트리 구조로 연결된다.

Header 컴포넌트안에 Nav 컴포넌트 생성해보기) ~/part3/vite-react_02/src/components/Header.tsx

> 리액트에서는 컴포넌트가 어디에서 랜더링되는지에 따라 컴포넌트 트리에서의 위치가 결정된다.
즉, 컴포넌트 간 포함 관계에 따라 트리가 구성되며, 이 구조는 애플리케이션의 동작 방식과 데이터 흐름에 중요한 영향을 준다.

....................리액트 컴포넌트의 주요 특징은 정리하면 아래와 같다.

*계층구조 : 컴포넌트는 부모-자식 관계의 계층 구조를 가진다. 부모 컴포넌트는 여러 자식 컴포넌트를 포함할 수 있으며, 자식 컴포넌트는 특정 부모 안에서만
랜더링된다. html에서는 형제 태그가 존재하지만, 리액트의 컴포넌트에는 형제 관계라는 개념은 명시적으로 존재하지 않다.

*단방향 데이터 흐름 : 리액트에서는 데이터가 항상 부모에서 자식으로만 흐른다.

부모 컴포넌트는 "props" 를 통해 자식에게 데이터를 전달할 수 있지만, 자식 컴포넌트는 부모의 데이터를 직접 변경할 수 없다.

props(properties의 줄임말)는 부모 컴포넌트가 자식 컴포넌트에 전달하는 데이터다. 함수의 매개변수처럼 자식 컴포넌트는 전달받은 props를 사용해 화면에 표시할 내용을
바꾸거나 동작을 제어할 수 있다.

*재사용성 : 한 번 정의한 컴포넌트는 여러 위치에서 반복해서 사용할 수 있다. 이를 통해 코드의 중복을 줄이고, 유지보수를 쉽게 할 수 있다.

*상태 관리 : 각 컴포넌트는 자신만의 상태(state)를 가질 수 있따. 상태가 변경되면 해당 컴포넌트는 자동으로 리랜더링되어 ui에 새로운 상태를 반영한다.
이 상태 변화는 컴포넌트 트리 하위에 있는 자식 컴포넌트에 영향을 줄 수 있다.

*랜더링 최적화 : 리액트는 가상 dom을 사용해 실제 dom과의 차이를 비교한 뒤 변경된 부분만 최소한으로 업데이트 한다!!
덕분에 빠르고 효율적인 랜더링이 가능하다.
