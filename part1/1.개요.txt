

모든 ui를 컴포넌트로 바라본다

컴포넌트 기반 아키텍쳐
-> 복잡한 ui를 작고 재사용 가능한 컴포넌트로 나누어 개발한다. 마치 레고를 조립하듯이..

가상 dom
->기존 자바스크립트나 제이쿼리 기반의 웹 개발에서는 화면에 표시하는 요소를 직접 dom에 접근하여 조작
->> 랜더링 비용이 매우 높다는 단점이 있음.

랜더링?
->화면에 푯히할 내용을 생성하고 그리는 과정. 랜더링 비용이 높다는 것은 화면을 다시 그릴 때 시간, cpu, 메모리 자원을 많이 소모한다는 의미.
특히 dom이 트리 구조로 깊게 구성된 경우, 일부 요소만 변경하더라도 전체 하위 요소를 모두 다시 그리는 경우가 많아 성능 저하로 이어짐.

리액트는 가상dom 개념을 도입.
->가상dom 은 실제 dom 복사한 자바스크립트 객체 형태의 트리 구조로, 메모리에서 관리.
실제 화면에 구성 요소를 추가하거나 변경하면 리액트는 이를 가상 dom에 먼저 반영. 모든 추가 및 변경이 끝난 뒤에 가상dom과 실제 dom을 비교. 이과정을 "디핑" 이라고 한다.
"디핑" 결과에 따라 실제 dom 실제 dom에는 변경한 부분만 최고한으로 업데이트하며, 이과정을 "재조정" 이라고 한다.


선언적 프로그래밍
-> 자바스크립트나 제이쿼리와 같은 기존 웹 개발 도구는 대부분 "명령형 프로그래밍" 방식을 사용. 이는 ui를 만들 때 '어떻게 변경할지'를 작성하는 방식. 
예를들어 화면에 표시된 숫자를 증가시키기 위해 모든 단계를 개발자가 직접 코드로 작성해야 됨.

반면 리액트는 "선언적 프로그래밍" 방식을 사용. 이는 ui를 만들 때 '무엇을 보여줄지' 를 선언하는 방식. 화면에 출력하는 숫자를 1씩 증가시킨다. 즉, 숫자 값을 바꾸는 상태만 변경하면됨.
숫자를 화면에 반영하는것은 리액트가 내부적으로 알아서 처리함.
