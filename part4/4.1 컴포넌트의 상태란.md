# 컴포넌트의 상태란

리액트 컴포넌트에서 데이터를 정의하는 가장 간단한 방법은 자바스크립트의 let 이나 const 키워드를 사용해 변수를 선언하는 것이다.

아래 코드를 작성하면 name 변수에 밑줄이 생긴다.

```javascript
export default function App() {
  let name = "철수";
  const age = 20;
  return (
    <div>
      <p>{name}</p>
      <p>{age}</p>
    </div>
  );
}
```

이는 타입스크립트 기반 컴포넌트에서는 let 키워드로 선안한 변수의 값이 변경되지 않아서 ESLint 에서 이를 경고 메시지로 표시하는것이다.\
그러나 이는 실행 오류가 아니기 때문에 애플리케이션을 실행하면 정상적으로 작동한다.

하지만 이 방식에는 치명적인 문제가 하나 있다. 변수에 할당된 값을 변경하더라도 컴포넌트가 리랜더링되지 않기 때문에 화면에는 변화가 나타나지 않는다.

아래코드에서 nameChange() 함수는 name 변수의 값을 '영희' 로 변경한다. 이로 인해 ESLint 경고는 사라지지만, 버튼을 클릭해도 화면에는 여전히 철수가 표시된다.

```javascript
export default function App() {
  let name = "철수";
  const age = 20;
  const nameChange = () => {
    name = "영희";
    console.log(name);
  };
  return (
    <div>
      <p>{name}</p>
      <p>{age}</p>
      <button onClick={nameChange}>value change</button>
    </div>
  );
}
```

이는 let 이나 const 키워드로 선언한 데이터가 변경되더라도 리액트가 해당 변화를 감지하지 못하기 때문이다. 그래서 리액트에서는 컴포넌트의 랜더링과 관련 있는 데이터는 단순한 변수 선언이 아니라 상태로 관리해야 한다.

**컴포넌트의 상태** 란 리액트 컴포넌트 내부에서 관리하는 데이터로 사용자와의 상호작용에 따라 변경될 수 있는 값을 의미한다. 즉, 상태는 리액트 애플리케이션이 동적 ui를 만들 수 있도록 도와주는 핵심 개념이다.

html과 css만으로 만든 일반적인 웹 페이지는 정적인 콘텐츠만을 보여준다. 하지만 사용자 입력, 버튼 클릭, api 요청과 같은 이벤트에 따라 화면을 업데이트하려면 동적 변화가 필요하다. 이때 상태를 관리하면 ui의 변화를 자동으로 반영할 수 있다.
